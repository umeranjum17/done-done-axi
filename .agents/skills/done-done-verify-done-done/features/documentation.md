# README and website first run

Sources: [README](../../../../README.md), [website](../../../../docs/index.html), [manual](../../../../docs/manual-cli.md), [real demo generator](../../../../docs/media/demo.mjs).

## Drive

1. Build with `npx tsc`. Use a fresh scratch directory outside the checkout, private DONE_DONE_HOME, npm prefix/cache and TMPDIR; never change the user's installed CLI or agent state. Make a fresh sample web app repo there (one committed page, no installable artifact, demo data named Umer). Run the README's three lines in a real terminal (tmux): `npm install -g done-done-axi` (with `--prefix` into scratch), `cd your-app && done-done init`, `done-done verify --outcome "<what works now>"`. init asks for the agent and judge: pick the user's configured judge route on their normal installed CLI/login, never a stub, and never copy credentials. The third line must end in a first result with no other command between: `result: pass`, a capture that shows the claim, and a receipt; open the capture. Save the terminal transcript and exits. An app that ships an installable artifact with no earlier release gets no verify skill from init today, so `doctor` names the gap instead; say so rather than calling that path proven.
2. Start `node docs/media/demo.mjs <fresh-scratch-directory> 0`; the server prints its OS-owned loopback port. It creates a real browser checklist and refuses to overwrite an existing demo repo. In its `app/` repo use the built CLI's `run --open --json`, saving stdout to `<scratch>/open.json`. Drive the browser with chrome-devtools-axi: add “Capture the real app”, check its checkbox, and save a real 400×140 DPR 2 `app.png` into the printed evidence_root. Open the screenshot and ensure the entire checked row and Done badge are visible. Seal the native run with `run --close <id>`, then run `check --json --outcome 'The Release checklist shows Capture the real app checked and marked Done.' <run>/app.png`, saving stdout as `<scratch>/check.json`. Use the user's configured judge for real, on their normal installed CLI/login; isolate done-done state but never copy credentials or replace the judge with a stub. Require a real pass with cached false, and preserve the native result, screenshot hash, run record and commit. Record a receipt and verify it at the sample-app HEAD. Open `/proof`, which displays the actual captured app and the check's real verdict/model and run commit, and capture at 400×230 DPR 2. This is the approved small public `docs/media/demo.png`. Inspect every pixel: no private paths, names or secrets. Board proof stays outside the repo.
3. Serve `docs/` on an owned loopback port (`python3 -m http.server <port> --bind 127.0.0.1 --directory docs`). For each width 1280 and 390 and each scheme light and dark, run `chrome-devtools-axi emulate --viewport <width>x900x1 --color-scheme <scheme>`, open the URL, wait for fonts and images, then `screenshot <evidence>/landing-<width>-<scheme>.png` and one `--full-page` shot. Follow README links and check internal anchors. Save overflow, image-load, console and failed-request readbacks. Long reference commands may scroll horizontally; the first-screen three-line block must fit without scrolling.
4. Capture the pushed README at `https://github.com/umeranjum17/done-done-axi/blob/<full-head>/README.md` at the same four cells. Use the file preview, not the repository file listing. After images decode, scroll the article to 90px below the viewport top so GitHub's file toolbar cannot cover its title. Capture the first screen and a full page. Do not change GitHub's DOM or theme classes; set the preferred scheme before navigation. Record the URL, head and image load results. Preserve baseline shots from the base commit and base landing page before editing; same widths, schemes, height and alignment.
5. Hero images: `node docs/media/hero.mjs` rebuilds `docs/media/.hero/hero-desktop.html` (888x543) and `hero-phone.html` (418x725) from the captured transcripts `docs/media/hero-run.txt` and `hero-refuse.txt`, and it fails when a quoted value is not in those transcripts. Screenshot each at `--viewport 888x543x2` and `--viewport 418x725x2` in light and dark, into `docs/media/hero-light.png`, `hero-dark.png`, `hero-phone-light.png` and `hero-phone-dark.png`. Open all four: every line legible, no clipped text, no paths or private names, and the judge's reason readable on the phone crop.
6. For design changes, fetch and capture the named reference pages with the same browser and matrix; place the real screenshots side by side (label comparisons, never call a montage a raw screenshot). Inspect every saved shot, using a full-size view or a readable contact sheet, including long-page slices. The first screen must show definition, audience, broken-product problem, a real product capture (the hero terminal images, never a drawn mock), the three lines ending in `verify` with the line that says it is the first result, and the with-or-without-Firstmate line, in that order. Reject clipped commands, overlapping text, missing images, broken links or a diagram presented as a real product capture. If motion did not change, no recording is required.

## Cleanup

Stop only the server PIDs started for this drive and stop your named chrome-devtools-axi session. Keep the proof and its index outside the checkout; remove task-owned disposable state only after retaining the proof. The first-screen demo requires a genuine configured-judge pass on the exact screenshot, not a stub or recorded-only result. Lower existing illustrations still disclose their deterministic judge.
