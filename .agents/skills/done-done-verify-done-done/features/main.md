# Main command

Part of the done-done verification map; reached at what README.md says a user runs first.

Source: `src/` (built to `dist/`), `skills/done-done/SKILL.md`, `integrations/firstmate/`, `package.json`, `package-lock.json`, `tsconfig.json`, `journeys/e2e.mjs`, `test/` and the landing page `docs/index.html`, which README.md mirrors. `done-done affected` maps a change to any of them to this feature's `e2e` journey.

## Sub-features

- Running version (`src/cli.ts`): capture `node dist/cli.js --version`, `--help` and `run --help`; help starts with `done-done <version>`, while `--version` keeps the bare version first and adds `pre-release` on line two only for a prerelease suffix. Drive a scratch copy of `dist/` and the shipped `skills/` data with its own package.json at `0.6.10-dev`, `0.6.10-rc.1+build.2`, and `0.6.10+build-dev` (metadata alone is not prerelease), with a link to this checkout's node_modules; capture all three outputs without changing this checkout's version. Integration: `test/cli.test.mjs` (`CLI version and help distinguish prereleases`); no browser or model.

- Improve one named journey with an instruction: `done-done run journey-improve` (`journeys/journey-add.mjs --improve`) uses a fresh greeting CLI fixture and the user's configured hosted agent to add a journey, enhance it, then `journey improve <name> "<instruction>"` adds an exact Unicode greeting check. Review the script, config instruction comment and appended verify coverage; commit and replay without an agent, then change only Unicode normalization and observe a failed assertion. Prove: `journey-improve.log` holds all three generation commands, diff summaries, scripts, actual captures and the negative control; `steps.json` records the flow. For clean-install proof, pack/install the candidate as below and run `DONE_DONE_TEST_CLI=<installed>/dist/cli.js node dist/cli.js run journey-improve`. Integration: `test/cli.test.mjs` (`journey add, enhance and improve generate reviewable recipes...`) covers required instruction, unknown names, no-agent/CI refusals, preserved settings/features/siblings, invalid rename/script diagnostics, spend gating, model-free CI replay and a new-check-only failure. Source: `src/cli.ts` and shared repo-state checks from `src/maintain.ts`. No browser is involved.
- Enhance one named journey: `done-done run journey-enhance` (`journeys/journey-add.mjs --enhance`) uses the same fresh fixture and user-configured hosted agent to add a greeting journey, then `journey enhance <name> "<focus>"` deepens it with empty, whitespace, Unicode, long, missing-name and unknown-command cases. Review the changed script, config focus comment and retained verify feature; commit and replay with no agent, then break only the empty-name edge and observe a failed check. Prove: `journey-enhance.log` holds both generation commands, diff summaries, generated scripts, live captures and edge-only failure; `steps.json` records the flow. For clean-install proof set `DONE_DONE_TEST_CLI` to the candidate package's installed CLI. Integration: `test/cli.test.mjs` (`journey add, enhance and improve generate reviewable recipes...`) covers public CLI dispatch, named focus/default, metadata and sibling preservation, invalid rename/no-agent/CI refusals, native invalid-script diagnostics with no writes, spend gating and model-free CI replay. Source: `src/cli.ts`, `src/maintain.ts` and `src/config.ts`. No browser is involved.
  Clean-install recipe: `npm pack --pack-destination <scratch>`, then `npm install --prefix <scratch>/install --ignore-scripts <scratch>/done-done-axi-<version>.tgz`; run `DONE_DONE_TEST_CLI=<scratch>/install/node_modules/done-done-axi/dist/cli.js node dist/cli.js run journey-enhance`. Keep the normal HOME for the user's already-signed-in generator; the fixture uses its own done-done config, repo and application state. The outer run seals the retained transcript at the checkout's clean HEAD; a recorded capture is not an independent judge verdict.
- Add a described journey: `done-done run journey-add` (`journeys/journey-add.mjs`) uses the user's configured hosted agent on a fresh greeting CLI app with a minimal verify setup. `journey add` must write a static capture/check script, config entry and verify feature map, print a diff summary and run the journey; commit its generated files and replay with no agent configured, then change the greeting and see its check fail. Prove: `journey-add.log` holds the live command results, generated recipe, diff and actual greeting capture; `steps.json` records the flow. No browser or Firstmate is involved. Integration coverage: `test/cli.test.mjs` (`journey add generates reviewable recipes...`) exercises the public CLI with a stand-in generation adapter and the real fixture app, including collision/no-agent/CI refusals and a nonzero check result. `src/cli.ts` owns generation; `src/agents.ts`, `src/config.ts` and `src/maintain.ts` supply init's existing agent, config and repo-state primitives. Help and docs: `done-done journey --help` prints a plain example of add, enhance and improve, and the README section "Write journeys in plain words" shows their real output; when that text changes, rerun the three commands from a clean install on a fresh greeting app and paste the actual output, never an edited one.

- The [`lint` gate](../../../../docs/reference.md#lint-check): the e2e journey writes one claim whose evidence file exists (`lint` must print `PASS`, exit 0) and one that names a missing file (`FAIL: evidence file missing or empty: ...`, exit 1); the pass and fail transcripts are in the outer run's `<run-id>.log`. Needs no judge or network. Drive by hand: write a `## Checks` file and an evidence folder, run `done-done lint <file> <folder>`, then lint the same evidence from a file in another folder to see the reuse fail; each run is a row in `$DONE_DONE_HOME/lint.log`. Size rules `checks.upstream_catch_up` and `checks.moved_from` (off by default): the e2e journey drives a 1,100-line PR URL through a stand-in `gh` (200 lines already upstream, 300 moved from a sibling repo): `lint` must print `FAIL: 1100 added non-generated lines` with both off and `PASS` with either on, all in the outer run's `<run-id>.log`; `test/cli.test.mjs` covers the other-owner and no-moved-from-line cases. `checks.generated_paths` (default none): the e2e journey lints the same 1,100-line PR (one file, `lib/big.js`) with `generated_paths: ["lib/**"]` and must print `PASS`, and `FAIL: 1100 added non-generated lines` with the key unset or a glob (`gen/**`) that misses; `test/cli.test.mjs` covers it too. A PR of any size is counted whole: the file list comes from every page of `pulls/<number>/files` (100 a page) and the net lines from the compare diff, and a failed page or diff fails instead of counting part of it. Drive `node --test --test-name-pattern='more than 300 files' test/cli.test.mjs`: its stand-in `gh` answers `pr view` with only the first 100 files, as GitHub does, and the pages with all 350; a 350-line PR must `PASS` where the first-100 sum (2000) failed before the fix, a 1,150-line PR must `FAIL: 1150 added non-generated lines`, a moved-from source at `lib/f320.js` on a later page must cancel its 300 lines, and a failing page 2 or compare diff must `FAIL` naming that call.

## Gotchas

See the [citation lookup contract](../../../../docs/reference.md#check-a-claim) rather than changing cwd or `evidence.root` to work around missing files. done-done gives no result without its judge, so the fixture repo sets a stub judge (deterministic, never a model) and a stub agent doctor finds but no step starts; a real judge is proven by a judged `check` with the agent and judge the user set. The fixture's look journeys embed this checkout's absolute path, so a local pre-commit hook that refuses home paths stops the fixture commit; run it with that hook off for the throwaway repo only (for example `GIT_CONFIG_GLOBAL=/dev/null`).
