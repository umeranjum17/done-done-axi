# done-done features

The repo's maintained verification map; a proof that drives one entry point is incomplete when this lists others.

- [README and website](documentation.md): real built-CLI demo, the three first-screen lines run to a first result, GitHub-rendered README and website before/after at 1280 and 390 in light/dark, link and layout checks
- [Installed-agent setup](agents-live.md): live Claude/Codex init, actual doctor probe, real CLI capture and judged receipt; explicit OpenCode free-tier limitations
- [Main command](main.md) (core journey): native run/check/receipt journey, including independent citation-base lookup and wrong-root controls, init's agent-written verify skill, and the real-product rule that refuses code-only proof
- [Upgrade in place](upgrade.md) (upgrade journey): the release path users take: install the last published done-done-axi, upgrade over it with this checkout's package, then drive the main command's e2e journey with the upgraded binary
- [Tier filtering](tier-filtering.md): journey tier selection and CI mode filtering with --tier flag
- [Flaky quarantine](flaky-quarantine.md): a journey that passes on its second run is named flaky with one warning line while the run passes
- [Test inventory ownership](inventory-ownership.md): `done-done run inventory-ownership`; a stray test file and a hand edit to an owned script fail lint by name, the same edit made by a journey command passes
- [QA planning](qa-planning.md): `done-done qa "<feature>"` plans a journey for new user-visible behaviour and marks fixtures, tests and internals no-test, recording stage planned and the reason
- [Test size bounds](size-bounds.md): `done-done run size-bounds`; an over-bound ci journey is stopped as slow, a large journey with no reason fails lint, large is night-only, `tests measure` reports five timings per test
- [Check time limit](check-time-limit.md): `done-done run check-fan-out`; `done-done check` on a repo of hundreds of journeys over one script web names a stale proof in seconds, and past `check.timeout` stops with an error that names the evidence line it was judging and a non-zero exit
- [Affected journey selection](affected-selection.md): `done-done run affected-select`; `done-done affected` follows sources, imports and path calls to a changed file, and sends unknown or global files to the whole local tier with the reason
- [QA writing](qa-writing.md): `done-done qa "<feature>" --write` adds one journey and config entry for a new command no journey covers, writes nothing on a second run or for a refactor
- [QA proof loop](qa-proving.md): `done-done run qa-prove`; `done-done qa "<feature>" --prove --max n` runs the covering journey through verify, fixes at most n times and seals a receipt for HEAD, or ends fixed on a done-done branch or fail at n
- [Test value](test-value.md): `done-done run test-value`; `tests value` plants faults in scratch copies and marks a test that catches them real, one that catches none slop, and a slower one catching the same faults duplicate, leaving the work copy unchanged
- [Affected selection audit](affected-audit.md): `done-done run affected-audit`; `done-done affected --audit <range>` finds a journey that failed at a receipted commit the map did not select, writes the file/journey pair to the feature that names it, prints recall, and `affected` then selects it
- [Test improvement plan](test-improve.md): `done-done run test-improve`; `tests improve --plan-only` proposes stage proposed with keep, drop and move rows and the gaps no test catches, and leaves git status clean
- [Applying a test plan](test-apply.md): `done-done run test-apply`; unproven combinations and demotions are refused, a faster-tier move replays faults, and a journey from `journey add` closes the gap
- [Minimum journey scope](minimum-scope.md): `done-done run minimum-scope`; `done-done verify --journeys <journey> --named-by <who>` drives only the journey the caller names, and the receipt records that list, who named it and the journeys not run (the affected ones too), while `affected` still exits 1
- [Affected file proof](affected-proof.md): `done-done run affected-proof`; `done-done verify --affected-by <files> --extends <head>` runs only the journeys the named files affect (the whole local tier for a file no journey covers), and the receipt links the prior receipt, the files, the journeys and that no review ran again
- [Registered test-script updates](registered-script.md): run `done-done run registered-script`
- [Live tier](live-tier.md): `done-done run live-tier`; `done-done run --tier live` runs only the `tier: live` entries, each bounded by its own timeout with no agent, one green or red row each (seconds), a red row exits 1 as a result and never a failed landing, and verify, affected and the landing path never run one
- [Command preflight](command-preflight.md): `node --test test/command-preflight.test.mjs`; with `check.preflight` on, `run`, `run --tier live` and `verify` refuse a command whose first word is no builtin, executable path or PATH binary with `command not found: <word> in <journey>` before any run, judge or agent call, and read env assignments and `sh -c` wrappers through
- [Verify drives base_ref beside the head, and a failing base_install names its cause](base-ref-verify.md): run `done-done run base-ref-verify`

- [Review base from policy](review-base-policy.md): `node --test test/review-base-policy.test.mjs`; with `check.review_base` on, `done-done review` takes its base from `jg-item base <project>`, refuses with `no policy row for <project>` or `review base command not found: jg-item`, and a named base still wins
- [Route fallback](route-fallback.md): `done-done run route-fallback` forces first author and judge failures, verifies YAML/tool-models precedence and actual route records, and rejects product failures without failover.
- [Cheaper judge, counted](cheap-judge.md): `node --test test/cheap-judge.test.mjs`; with `judge.cheap_first` two cheap verdicts that agree stand and the configured judge is called only when they differ, and the receipt lists every call with its tokens (`null` when unreported)
- [Red before green](red-before-green.md): `node --test test/red-before-green.test.mjs`; `done-done receipt --new-test <file>` runs a declared new test on the base commit with the file copied in from head and refuses the receipt when it already passes there (exit 77 is skipped, never a pass); the receipt records `new_tests` with base red
- [Gut check](gut-check.md): `node --test test/gut-check.test.mjs`; with `check.gut_check` on, `done-done receipt --new-test <file>` stubs the test's one target to do nothing in a scratch checkout of HEAD and refuses the receipt when the test still passes (zero or two targets refuse `gut check needs exactly one target`, exit 77 is skipped, never a catch); the receipt's `new_tests` rows gain `gut`
- [Reuse a sealed PASS](reuse-sealed-pass.md): `node --test test/reuse-sealed-pass.test.mjs`; with `check.reuse_pass` on, a run or verify whose tree, journey and command match a sealed PASS receipt does not run again, names the sealed run as `reused_from` and exits 0, and runs as before on a changed tree or command, a dirty tree, an edited capture or the switch off
- [False refusals counted](false-refusals.md): `node --test test/false-refusals.test.mjs`; with `check.count_false_refusals` on, `done-done report false-refusals` counts per check each FAIL that a later PASS on the same git tree followed as a false refusal, lists the catches and the catches-to-false ratio, and says the switch is off and counts nothing when it is
- [Skip is not proof](skip-not-proof.md): `node --test test/skip-not-proof.test.mjs`; with `check.skip_is_not_proof` on, run and verify give the test command `JG_TEST_SKIP_EXIT=77` and record an exit 77 as skipped, never a pass: a run that only skipped gets no receipt, a run with a skipped and a passing cell keeps it and lists the skip, and the switch off or absent runs as before
- [Mise shim in a sealed run](mise-shim.md): `node --test test/mise-shim.test.mjs`; a private HOME no longer hides the host's mise: its config, data, state and cache folders stay visible and the host's `config.toml` is added to `MISE_TRUSTED_CONFIG_PATHS` (a caller's value is kept and extended), so a shim such as python3 runs, in the instance and in every command done-done spawns (`run -- <cmd>`, a journey, the suite step); a host with no mise config gets no mise variable
- [Affected journey selection: chains, fallbacks and shadow plans](affected-select.md): run `done-done run affected-select`
- [Tier filtering and shadow batch deadlines](tier-filtering.md): run `done-done run tier-ci`
